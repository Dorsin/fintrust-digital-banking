Part D & E — Baseline Model Development & Evaluation¶

In this section, we build and evaluate a baseline classification model to establish a performance benchmark for transaction risk identification.

1. Baseline Algorithm Choice: Logistic Regression¶

We select Logistic Regression as our baseline model for the following technical reasons:

  • Linear Benchmark: It provides a simple, highly interpretable baseline that evaluates class separability under linear assumptions
  • Calibrated Probabilities: It directly estimates class probabilities, allowing fine-grained threshold tuning for risk screening
  • Class Balance Management: Incorporating class-weight balancing (class_weight='balanced') mitigates the moderate class imbalance (~20% flagged transactions)

2. Data Preparation & Preprocessing¶

  • Feature Selection: Non-predictive identifiers (Transaction_ID, Customer_ID) and timestamps (Transaction_DateTime) are excluded
  • Preprocessing Pipeline: Categorical features are encoded using OneHotEncoder(drop='first'), and continuous numerical features are standardized using StandardScaler()
  • Data Splitting: A 80/20 stratified split (train_test_split(stratify=y)) ensures that class distributions remain consistent across training and test sets

3. Metric Selection Strategy (Part E Rationale)¶

For financial risk screening, metrics carry distinct operational trade-offs:

  • Recall (Sensitivity): Primary metric. False Negatives (unflagged risky transactions) expose the institution to financial loss and compliance penalties
  • Precision: Measures false alarm rates. False Positives create operational overhead during manual reviews
  • F1-Score & PR-AUC: Evaluate global model discrimination and balance between Precision and Recall.

1. Performance Overview vs. Baseline¶

The tuned Random Forest implementation demonstrates an operational trade-off shift compared to the Logistic Regression baseline, though overall discriminative capacity on imbalanced data remains static:

2. Critical Assessment¶

Strengths¶
  • Operational Workload Reduction: By reducing false alarms from 681 down to 443 cases, the Random Forest significantly decreases the manual verification burden on review processes
  • Higher Majority-Class Specificity: The non-linear split structure handles unscaled features more conservatively, improving non-risk (Class 0) identification (77% recall vs. 65% baseline)
Limitations¶
  • Stagnant PR-AUC Boundary: The Precision-Recall curve comparison confirms that switching to a non-linear ensemble does not shift the precision-recall frontier upward (PR-AUC = 0.3050 vs. 0.3051). Both models face the same fundamental trade-off limits
  • Increased Risk Leakage: Capturing only 197 out of 470 actual risk cases (Recall = 41.91%) results in 273 unflagged high-risk transactions passing through undetected
  • Probability Thresholding Sensitivity: Standard 0.5 decision thresholds heavily penalize recall in tree ensembles trained on imbalanced distributions, even with class_weight='balanced'

3. Recommended Next Steps & Algorithm Roadmap¶

To break through the 0.3050 PR-AUC ceiling and improve risk coverage without exploding false positives, the following technical strategies are recommended:

A. Advanced Machine Learning (Gradient Boosting Frameworks)¶
  1. XGBoost / LightGBM:
    • Leverage native imbalance control (scale_pos_weight) combined with custom focal loss objectives to focus tree splits on hard-to-classify risk boundary cases
  2. CatBoost:
    • Optimizes categorical target encoding natively, helping isolate complex interaction terms without losing split granularity
B. Decision Threshold Optimization & Probability Calibration¶
  1. Precision-Recall Threshold Tuning:
    • Instead of a default 0.5 classification threshold, sweep prediction probabilities along the PR curve to select an operational threshold optimized for target Recall (e.g., locking Recall at 75%)
  2. Post-Hoc Probability Calibration:
    • Apply Isotonic Regression or Platt Scaling to align model confidence scores with true empirical risk prevalence before applying decision thresholds
C. Deep Learning & Anomaly Detection¶
  1. Autoencoders (Unsupervised / Semi-Supervised):
    • Train a Neural Autoencoder exclusively on standard non-risk transactions (Class 0) to flag high reconstruction error cases as novel risk anomalies
  2. Resampling Strategies:
    • Apply SMOTE-Tomek or Edited Nearest Neighbors (ENN) prior to model fitting to clean noisy boundary samples between majority and minority synthetic classes

3. Critical Assessment & Project Governance¶

Model Limitations¶

  • Logistic Regression: Constrained by linear decision boundaries, failing to naturally capture complex interactions without manual cross-term engineering
  • Random Forest: Suffers from feature importance bias toward high-cardinality continuous variables and exhibits reduced recall under standard thresholding on imbalanced classes.

Data Limitations¶

  • Imbalanced Class Ratio: Class 1 transactions represent a minority (~20%), constraining class boundary definition without advanced resampling
  • Feature Scope: The dataset lacks historical longitudinal features (e.g., 6-month historical dispute rates or device fingerprint history)

Possible Sources of Bias¶

  • Synthetic Generation & Artifact Bias: Because the dataset is synthetically constructed (algorithmically or manually generated for benchmark purposes), ground-truth labels reflect predefined creation rules rather than organic human fraud behaviors. Models risk over-learning these artificial generation artifacts instead of subtle real-world fraud signatures
  • Label Prevalence Bias (Distorted Prior Probabilities): The synthetic dataset features an artificially elevated risk rate (~20%), which severely deviates from real-world financial environments where fraud typically accounts for less than 1–2% of total volume. This inflated prior probability biases the model's predicted risk distribution toward over-flagging transactions
  • Deterministic Feature-Label Coupling: Synthetic creation pipelines often embed rigid, hand-crafted feature associations (e.g., directly linking Transaction_Type_Transfer or Is_Night_Transaction to high risk scores). This forces models to pick up author-defined heuristics rather than complex, multi-layered risk interactions

Areas Requiring Further Investigation¶

  1. Gradient Boosting Architectures (XGBoost / LightGBM ): Upgrade from standard Random Forest to sequential gradient boosting to capture higher-order non-linear interactions while maintaining feature split controls
  2. Probability Calibration & Prior Alignment: Apply Post-Hoc Probability Calibration (e.g., Platt Scaling or Isotonic Regression) to recalibrate predicted scores, correcting the artificial prevalence bias (~20% risk rate) back toward realistic operational base-rates (<1-2%)
  3. Model Explainability & Synthetic Rule Auditing (SHAP / LIME): Deploy SHAP (SHapley Additive exPlanations) values to verify whether models are learning genuine multi-variable risk interactions or simply exploiting simple, author-defined generation heuristics
  4. Cost-Sensitive Threshold Tuning: Align final decision boundaries with explicit business cost matrices (weighing the financial loss of false negative fraud cases against the operational overhead of manual review queues).
